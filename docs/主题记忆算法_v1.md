# 语料驱动的主题关系学习与约束再现：算法与实现 v1

版本：2026-10-17。状态：工程原型，可复现实验；尚未完成听觉记忆或审美质量的人体实验。

本文对应 `score_learning/theme_memory.py`、两种 grammar 作曲器、增量学习脚本和配对评估脚本。论文写作时应固定代码提交、策略文件及语料缓存摘要，不能把后续修改混入本版本结果。

## 1. 问题与研究范围

现有系统分别学习和声转移、节奏模板、音程分布、乐句轮廓及终止公式。局部统计能约束风格和合法性，但不保证一首新曲内部存在可辨认的材料联系。原有记忆机制主要是整段复用、小节照抄或模进；后者还会在旋律无解时被移除。

本版本的目标是学习**同一作品内的跨乐句材料关系**，以它规划新曲中的主题再现，并把主题作为求解约束。它不把训练曲的主题片段直接复制到新曲：运行期主题来自本次生成的材料。

需要区分：

- 结构再现：后续片段与先前材料之间可验证的音程、节奏联系。
- 感知辨识：听者能否认出该联系。
- 旋律记忆：延迟后能否回忆、哼唱或识别主题。

本版本测量第一项，提供试听支持第二项的探索；不能据此宣称第三项已经提高。

## 2. 表示与相似度

单声部片段写作 `x = [(p_i, d_i)]`，其中 `p_i` 为 MIDI 音高，`d_i` 为四分音符时值。建立：

\[
\Delta_i=p_{i+1}-p_i,\qquad r_i=d_i/\sum_j d_j.
\]

精确签名为音程元组及保留三位小数的归一化时值元组。整体移调或等比例速度变化不会改变该签名。至少包含四个事件且出现三个不同音高，才作为有效动机候选，以排除单音保持和两音循环造成的明显假阳性。该过滤不表示真实音乐中的两音动机不重要，只是本原型的适用边界。

近似匹配将 `(Δ_i, r_{i+1})` 序列进行编辑距离对齐。插入、删除的代价均为 1，替换代价为：

\[
 c=0.75\min(|\Delta-\Delta'|/4,1)
 +0.25\min(|\log_2(r/r')|,1).
\]

以较长 token 序列长度归一化距离，得 `S = max(0, 1-D/max(n-1,m-1))`。阈值为 `S ≥ 0.82`。权重、阈值和有效动机过滤均为**工程超参数**，并非从语料自动估计；它们需要在独立验证集校准。

## 3. 学习算法

### 3.1 数据与划分

复用现有结构化语料缓存。训练排除 `is_heldout(id)` 为真的作品，即作品 ID 的 MD5 对 10 取模为 0 的分组。策略记录训练 ID 集合的 SHA-256、语料缓存文件 SHA-256 和实际样本数。该划分是作品 ID 级划分，不等价于作品家族或作曲家级隔离，可能仍有近重复作品。

众赞歌以现有 fermata 乐句边界和逐拍女高音骨架为单位。其他风格沿用现有八小节单元；它是分析网格，不保证符合人工乐句边界。后续应加入基于终止、休止和结构新颖度的可变长度分句。

### 3.2 作品内的动机关系挖掘

对每首训练曲独立执行：

1. 对 4、6、8 个事件的连续窗口建立精确签名索引；每句每种长度最多扫描前 32 个候选起点。
2. 后续句在前 8 个候选起点寻找前句中的对应材料。先查精确索引；未命中时，对每种长度最近 32 个来源候选做近似对齐。
3. 仅在不同乐句之间匹配，不把重叠的同句窗口视为跨句记忆。
4. 每个目标句最多贡献一次关系：优先更高相似度，再优先更长的片段。这样避免把同一重复段落的多个重叠窗口逐一计票。
5. 汇总目标位置（中间句/末句）、来源距离、动机长度及持续时间。描述性地统计原样重复、移调重复和近似变化。

学习产物是出现次数与条件频率，不包含具体训练旋律。近似关系数量不等于人类主题标注的正确数量：没有人工真值时，这些是模型发现的候选关系。

### 3.3 运行期使用的参数

当前实际用于生成的参数：

- `by_phase` / `recall_probability`：目标位置的再现概率。
- `lag_counts`：主题来源与目标之间的单元距离。
- `length_counts`：众赞歌的候选动机长度；受乐句容量与终止区限制。
- `duration_median_ql`：其他风格的主题头部长度，换算并限制为 1–2 小节。

`transform_counts` 在本版是描述性学习结果，尚未用于学习变形操作的完整生成分布。移调候选固定为 `0, +2, -2, +5, -5, +7, -7` 半音；不能在论文中把这些候选说成自动学到的音程。

## 4. 规划与约束生成

### 4.1 关系规划

首句提供新材料。后续句按目标位置概率决定是否再现，再按来源距离分布选择之前已经生成的材料。引用只能向后指向既有单元，因而不会形成循环依赖。

对于存在训练再现证据、且至少三句/段的新曲，如果本轮抽样完全没有再现，则安排一次从首句到末句/段的引用。这是**最少一次的工程先验**，不是语料学习结论。

### 4.2 众赞歌：主题约束下联合选择和声与女高音

从指定来源句寻找有效片段，最多保留六拍，并保证目标句最后三拍留给终止公式。生成过程中对主题位置的 `(和弦, 女高音)` 状态集合进行音高筛选，然后执行既有 FFBS。

因此，和声是在主题约束下选出的，而非先完成四声部后再替换音符。随后仍执行低音及内声部搜索，全部原有硬规则继续有效。

每次局部搜索尝试有限的移调与终止候选。前四轮尝试带主题的搜索，第五轮允许明确降级到无主题候选。追溯记录来源、来源偏移、长度、移调、实际相似度及 `new / realized / relaxed` 状态。约束失败不应被统计为成功再现。

已有 Barform 机制继续保留；本模块的消融实验不是整个历史记忆系统的开关实验。

### 4.3 其他风格：主题头部约束与和声重搜

新段落需要主题回忆时，沿用来源段前 1–2 小节的节奏，尝试兼容目标和声的移调，并固定该区域旋律音高。与和声冲突或旋律无解时，重新搜索和声及后续旋律，而不在该次约束搜索中直接丢弃主题头部。

最多尝试五轮主题约束候选，第六轮允许无主题降级，显式记录 `relaxed`。已有整段引用与四小节头部变奏仍由历史段落记忆机制处理。新模块不叠加重复约束来覆盖这些引用。

这仍是有界候选重搜，**不是**对所有和声、变形及配器组合的全局最优联合搜索。

## 5. 追溯、独立验证与消融

主题追溯通过 kernel 保存于生成规格的 `grammar.theme_memory`。直接调用两种作曲器时，也可从返回值 `theme_memory` 读取。

独立验证器重新解码最终 spec 的实际音符事件流，不读取“回忆第几小节”等报告文字。众赞歌在四分音符位置采样实际发声的女高音；其他风格使用主旋律音符事件，管弦乐选择小提琴 I。分别计算：

- **窗口再现率**：后续句是否出现与前句相似度达到阈值的四事件窗口。
- **精确开头再现率**：后续句开头四事件是否与前句某窗口有相同音程和归一化节奏。
- **整句重复率**：后续整句是否与前句具有相同精确签名，用于观察是否退化为整句重复。
- **约束实现数/计划数**：搜索追溯中的实现情况，与独立谱面指标分开记录。
- **硬规则违例**：使用原有风格检查器，不以主题得分替代音乐合法性。

短窗口在调性音乐中可能偶然匹配。窗口再现率可能饱和，不能单独充当音乐质量指标。整句重复率也不天然越低越好，AABA 等曲式本来需要再现。应结合体裁、人工标注与盲听解释。

`theme_memory_v1.py` 对相同种子分别关闭/开启新模块，历史记忆在两组中都保留。种子相同不保证候选完全相同：新模块会改变随机数消耗和搜索路径，因此这是固定种子的系统级配对对照，而非对完全相同音符进行局部处理。

另修正历史 `leadsheet/eval_memory.py` 的全记忆关闭逻辑：配置位于 `subs[sub]`；仅修改角色仍可能保留同标签再现与同族变奏，因此现在直接关闭对应规划器。历史文字统计同时排除“仅节奏”的回忆，但它仍只是 trace coverage，不是感知结果。

## 6. 复杂度、复现与试听

长度为 `l` 的两片段编辑距离时间为 `O(l²)`，空间为 `O(l)`。学习的近似候选数通过长度集合、32 个来源候选和 8 个目标起点限制。精确索引可随作品长度增长；近似检索窗口有界，会漏掉更早的变体。生成复杂度由原有动态规划决定，新模块增加有限次数的状态筛选或候选重搜，不提供总体最优性保证。

```bash
# 需先准备仓库现有的 runs/grammar_cache 语料分析缓存；本脚本不联网下载
# 不修改大型历史 grammar.yaml；生成有语料摘要的增量策略文件
venv/bin/python scripts/dev/learn_theme_memory.py

# 回归测试
venv/bin/python -m pytest tests/test_theme_memory.py -q

# 固定种子配对实验，以及实际 /compose-grammar 路径的试听文件
venv/bin/python scripts/eval/theme_memory_v1.py --seeds 12 --audio
```

应用内示例：

```text
/tempo 72 /compose-grammar G 16 downbeat seed=theme-v1-demo memory=on
/compose-grammar 民谣 32 seed=theme-v1-demo memory=on
/compose-grammar G 16 downbeat seed=theme-v1-demo memory=off
```

`memory=off` 仅关闭本版新主题模块，不关闭历史 Barform、段落引用或小节照抄。未安装增量策略的旧规则脚本保持原有生成机制；强行 `memory=on` 也不会凭空产生训练关系。

试听选择 music21 自带的 Bach BWV 318（该作品 ID 属于当前划分的留出组），以及通过实际命令入口生成的 G 大调原创众赞歌。两者统一使用钢琴、72 BPM、MIDI velocity 80、GeneralUser GS SoundFont、44.1 kHz、相同混响。音符内容保留，完整作品长度不同；这不是严格的偏好实验，也不是新旧算法音频 A/B。生成曲与巴赫的比较用于听辨，算法消融另见 JSON。

## 7. 后续论文可以检验的假设

- H1：在控制体裁、长度和合法性的条件下，新模块提高最终谱面上的主题开头再现率。
- H2：这种提高不以整段机械重复的大幅增加为代价。
- H3：听者更容易识别主题回归，并认为段落联系更清楚。
- H4：延迟后的旋律识别/哼唱成绩提高。

当前自动实验最多支持对 H1/H2 的有限结构性观察；H3/H4 需要新设计的盲听、延迟记忆任务、足够样本量及预注册分析。不能把本次小样本种子实验直接表述为论文中的显著性结论。

下一阶段应增加：人工主题/变体标注集、不同长度的分句、学习变形操作分布、近似节奏变形生成、主题与和声的更充分联合搜索、短时/长期可变阶序列模型，以及更严格的近重复与作品家族隔离。

## 8. 可用于论文的方法段落（英文草稿）

> We augment a rule-constrained symbolic composition system with a corpus-derived thematic recurrence policy. Within each training piece, melodic windows are represented by signed pitch intervals and normalized durations. Exact hashing and bounded edit-distance alignment identify candidate cross-phrase relations. The resulting model stores aggregate distributions over recurrence position, reference lag, and motif length rather than source melodies. At generation time, thematic material is drawn from earlier phrases of the newly generated piece. For chorales, motif pitches restrict the joint harmony–soprano state space before forward-filtering backward-sampling and subsequent voicing. For leadsheet-based styles, a short thematic prefix constrains melody search while harmony candidates are retried. Bounded search failures are explicitly logged as relaxed constraints. An independent verifier decodes the final symbolic event stream to measure recurrence, while existing rule checkers assess legality. These structural measures are not interpreted as evidence of listener memorability without a separate perceptual study.

这段草稿描述本版实际实现，不声称新算法的学术原创性或已证明的审美提升。研究贡献与相关工作差异应在正式论文中另行论证。

## 10. 本次本地验证记录

2026-10-17 的配对实验使用 12 个众赞歌种子和民谣、奏鸣曲、爵士各 3 个种子，每个种子比较新模块关闭与开启，共 42 份生成结果。

- 众赞歌的精确开头再现率（每曲比率的均值）为 10.28% → 85.42%；整句重复率为 2.78% → 2.78%。
- 众赞歌规划了 56 次短主题引用，约束搜索直接实现 51 次，其余情况保留明确降级追溯。
- 奏鸣曲的精确开头再现率为 22.22% → 44.44%；本次 3 个种子的民谣和爵士该指标没有改善。
- 42 份输出的既有硬规则检查均为零违例。
- 自动回归分两次完成：grammar/历史记忆相关 26 项通过；新增主题、历史记忆与编辑/导出相关 126 项通过。两次覆盖存在重叠，不能相加为不同测试的总数。
- 两个 WAV 的峰值分别约 0.886 与 0.877，RMS 分别约 0.159 与 0.151，44.1 kHz、16-bit、单声道；没有接近满幅的削波样本。这里只验证文件与电平，不代表已完成人类听审。

原始明细：`runs/theme_memory_v1/paired_evaluation.json`。学习来源及摘要：`learning_report.json`。音频设置与文件摘要：`listening_manifest.json`。生成命令及谱面规格：`generated_trace.txt`、`generated_spec.json`。

上述数据是工程规模的探索结果，尚未做显著性检验，也未调参寻找最佳种子。四事件相似度阈值是固定超参数，可能过于宽松；本次结果已经出现窗口再现率饱和，因此需要更长窗口、人工主题标注和风格适配的评价。

表示局限还包括：当前符号相似度使用有声音符的时值，不单独编码休止位置或起音间距；众赞歌采用逐拍骨架，不能完整反映装饰音的感知效果。试听文件可以检验实际听感，但不能替代上述缺失的标注与实验。

## 11. 四声部试听暴露的问题与下一版目标

2026-10-17，用户比较新生成的弦乐四声部与 BWV 1068 Air 后，反馈生成曲没有可感知的主旋律，仍缺乏记忆性。这是一次个体试听反馈，不是群体实验；它明确说明本版结构再现指标不能作为听觉目标已经实现的证据。

对应文件为 `runs/orchestral_four_voice/generated_trace.txt` 与 `comparison.json`。本次输出的四个八小节段落标签为 ABCD，只有第三、第四段分别引用前文一小节。32 小节中的两次一小节引用不足以建立持续的主题身份。

`accompaniment_quartet` 对两个内声部使用同一半拍起音循环，因此第二小提琴与中提琴的起音集合 Jaccard 为 1.0；相邻同音比例分别约 86.29% 和 85.48%。这些伴奏行为来自硬编码模板，不是模型学会的独立声部织体。统一音色和力度进一步削弱了主次，但单独改变混音不能修复主题内容与乐句组织。

下一版应分开解决三个问题：先生成并筛选具有节奏身份、轮廓与终止方向的完整主题乐句；显式安排主题的陈述、应答、发展和回归；再根据旋律角色与和声生成具有独立运动的伴奏。独立不意味着刻意错开所有起音，合奏同步在音乐上可以合理存在。不能把随机错拍、增加复制次数或调高第一声部音量当作学习成果。

验证应同时检查主题跨乐句关系、声部角色与起音耦合，并采用盲听识别、延迟哼唱或主题辨认任务。BWV 1068 应保留为外部比较曲，不以直接复制其旋律作为改进手段；当前生成器的古典弦乐训练风格与该巴洛克参考也有差异，比较不能归因于单一算法因素。以上为后续设计目标，尚未实现。

### 11.1 v2 工程修正

在上述试听反馈后实现了一个限定范围的 v2。启用主题记忆的 24/32 小节弦乐四重奏采用 ABA/ABAC 形式先验，第一小提琴完整回归八小节 A 主题；这是一项显式工程先验，应与从语料估计的主题关系区分。4/4 伴奏把第二小提琴改为拍后半短应答、中提琴改为和声长音，替换两个声部共享的半拍脉冲模板。

固定新种子 `orchestral-four-voice-v2` 的结果中，第二小提琴—中提琴起音 Jaccard 从 1.000 降至 0.006，四声部同时起音比例从 22.81% 降至 0.35%，中提琴相邻同音比例从 85.48% 降至 30.77%。第一小提琴第 1–8 与第 17–24 小节的 MIDI 音符事件完全一致。相关 grammar、记忆、比较与导出回归共 43 项通过。

这一版建立了清楚的旋律回归点并解除中声部锁步，但第二小提琴与低音的同音重复仍高，伴奏还不是从多声部轨迹学习的独立对位。结果文件和完整限制见 `runs/orchestral_four_voice_v2/优化与比较报告.md`。

### 11.2 v3：从手工位置约束改为联合关系学习

试听表明，把曲式固定为 ABAC、指定第 1–2 小节在第 3–4 小节重复，仍属于人工作曲规则。v3 已移除这两项规定。曲式重新使用 grammar 从训练集学到的分布；主题内部关系由 `learn_policy` 在训练曲的八小节乐句中挖掘。

训练器对一小节和两小节候选同时统计：来源位置、回答位置、跨度、来源音符密度、旋律变换类型，以及来源与回答首和弦的相对根音移动。策略文件只保存这些聚合计数，不保存训练曲旋律。生成器从联合分布采样一个关系，用当前风格已学习的节奏模板形成来源材料，再让回答的节奏、和声与音程轮廓共同服从该关系。最终符号结果必须达到训练器使用的 0.82 相似度阈值，否则重新搜索。

当前 string-quartet 训练缓存共 190 首，allegro 训练划分中的乐句内部候选有 1976 个，匹配 419 个，匹配率 21.2%。五个独立生成种子的学习关系位置和跨度不同，最终主题回答相似度均为 1.0，硬规则违例均为零。相关数据写入 `theme_memory.yaml` 的 `intra_phrase` 字段。

这仍不能等同于学到 BWV 1068 Air 的听觉品质。当前 strings/allegro 数据主要是古典弦乐快板，最常见来源密度为每小节八个起音，因此模型会学到比 Air 更忙的主题。若论文目标是巴洛克慢乐章的长线条，应新增同类、多作品训练集，并把 BWV 1068 完整留出；还需以盲听识别或延迟哼唱标签训练感知排序器。只把 BWV 1068 加入训练再与它比较会造成数据泄漏。

### 11.3 v4：从单次回答扩展为学习动机发展链

钢琴对比进一步显示，单次“问答”不足以形成贯穿全曲的记忆。新版在每个训练乐段内寻找同一个来源动机的全部后续回归，并聚合学习来源位置、动机跨度、回归位置序列、实际出现次数、来源音符密度，以及每次回归对应的和声根音位移。

运行时从聚合计数中抽取一条发展链，现场生成来源动机，再在学到的多个位置进行和声相容的移调回答。采样按训练集中实际出现的回归事件加权，所以包含多次发展的模式会根据语料频率自然获得更高概率；算法没有固定 ABA、ABAC 或特定小节号。导出前会逐次核验所有回答，任一回答低于训练阈值就重新搜索。策略仍只保存统计计数，不保存训练作品的音高或节奏片段。

### 11.4 v5：开头主题层级

试听否定了“任意位置的重复都能建立逻辑”这一假设。v5 单独统计八小节段落开头一至两小节在后文的回归关系，并让生成器优先使用这组分布。奏鸣曲快板缓存中共有 283 个可识别的开头主题回归实例；常见关系包括开头一小节在第 2、3、5 小节回答，以及开头两小节在第 3、5 小节回答。

生成器现在必须先陈述主题，再进行回答，不再允许中间随机出现的小节被事后解释为主主题。主题原子采用五级粗轮廓和量化节奏比例，实际音高仍由和声相容的旋律搜索决定。该改动建立了时间上的主题层级，但尚未学习完整的呈示、延伸、碎片化、终止功能标签；其听觉效果仍需试听判断。
